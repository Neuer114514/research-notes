## 一、计划定位

**核心原则**：以「动手跑通」为主线，把检索、阅读、复现、汇报串成一条完整链路。

三条主线：

1. **由浅入深、前后衔接** —— 第 1 周打地基（环境 + Python + 记录习惯），第 2 周入门深度学习与 PyTorch，第 3 周进入大模型 / 多模态 / 智能体 / 强化学习，第 4 周完成一次论文复现与汇报。
2. **动手优先** —— 每天必须「写出东西」：可运行的代码、笔记条目、实验日志或 PPT 页面。**只看视频不算完成当日任务。**
3. **AI 辅助但不依赖** —— 每天都会用 AI，但要记录「AI 说了什么、我验证了什么、我修正了什么」。

### 每日时间分配（工作日 3 小时）

| 时段 | 时长 | 用途 | 要点 |
|------|------|------|------|
| 第一段 | 60 分钟 | 看课程／读论文／查资料 | 带着问题看，随手记关键词和疑问 |
| 第二段 | 90 分钟 | 写代码、跑实验（最重要） | 必须亲手敲或逐行改，不要只复制粘贴 |
| 第三段 | 30 分钟 | 整理笔记 + 写日志 + 规划明天 | 记录报错与解决过程，这才是可复用的资产 |

> 提醒：任何单点问题超过 1 小时仍未解决，就先用替代方案绕过（换小模型、换数据集、换更简单的示例），把问题记进 `faq.md`，带着具体报错去问师兄师姐或老师。

## 六、怎么更新这份文档

每天三步：

```bash
# 1. 写今天的日志
cp daily/模板.md daily/2026-10-28.md

# 2. 更新进度数据：把当天那条 status 改成 "done"，并在 daily 数组里加一行时长
#    编辑 data/progress.js

# 3. 提交推送，网页约 1 分钟自动更新
git add .
git commit -m "docs: 第 5 天 检索能力"
git push
```

| 我想改什么 | 改哪个文件 |
|-----------|-----------|
| 今天学了多久 | `data/progress.js` → `daily` |
| 某天任务完成了 | `data/progress.js` → `plan` 里那条的 `status` 改成 `"done"` |
| 每周完成天数 | `data/progress.js` → `weeks` 里的 `done` / `hours` |

| 论文笔记（第 2 周起） | `papers/` |
| 练习代码 | `code/weekN/` |

1. GitHub 新建仓库 **`research-notes`**（Public，不勾 README）

   ```bash
   git remote add origin https://github.com/<你的用户名>/research-notes.git
   ```
