> 遇到的最大障碍（含完整报错）：
> ```
> git@github.com: Permission denied (publickey).
> fatal: Could not read from remote repository.
> ```
> 用 SSH 地址 push 被拒，本地没有配置 SSH key。
>
> 解决方式（自己查到的 / AI 给的 / 问人的）：
> - 自己查 GitHub 文档确认是 SSH key 未配置；
> - 按文档 `ssh-keygen -t ed25519 -C "邮箱"` 生成密钥，把公钥加到 GitHub → Settings → SSH and GPG keys；
> - 用 `ssh -T git@github.com` 验证连通后再 push，成功。
>

## 关键知识点

| 命令 | 作用 | 我踩的坑 |
|------|------|---------|
| `git add .` | 把改动放进暂存区 | 曾误以为 add 就等于提交 |
| `git commit -m "类型: 描述"` | 生成一次存档 | 提交信息写成"修改"不利于回溯，改用 `feat/docs/fix` 前缀 |
| `git push` | 推到远端 | 第一次要配 SSH key，否则 Permission denied |
| `.gitignore` | 忽略缓存与虚拟环境 | 不写的话 `__pycache__/`、`.venv/` 会被提交上去 |

## 一句话复盘

git 的三个区域（工作区 → 暂存区 → 仓库）搞清楚之后，提交就不再靠背命令了。
