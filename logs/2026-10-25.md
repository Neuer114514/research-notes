# 2026-10-25 学习日志

## 今天学了什么

搞懂了 Git 的分支模型，能在独立分支上改代码再合并回主线。

- 知识点 1：`branch` / `switch` / `merge` 的使用场景
- 知识点 2：合并冲突是怎么产生的、怎么解决
- 知识点 3：`git log --graph` 看提交图谱

## 学习内容详情

### 1. 常用命令

```bash
git switch -c feature/xxx   # 新建并切换到分支
git add . && git commit -m "feat: xxx"
git switch main
git merge feature/xxx       # 合并回主线
git branch -d feature/xxx   # 删掉已合并的分支
```

### 2. 冲突解决

两个人（或两条分支）改了同一文件的同一段，Git 无法自动判断保留谁，
就会标记为冲突：

```text
<<<<<<< HEAD
我的改动
=======
别人的改动
>>>>>>> feature/xxx
```

手动改成想要的内容，删掉标记行，再 `git add` + `git commit` 即可。

### 3. 提交信息规范

统一用 `类型: 描述` 的格式，方便以后回溯：

| 前缀 | 含义 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修 bug |
| `docs` | 文档改动 |
| `refactor` | 重构 |

## 遇到的问题与解决

| 问题 | 原因 | 解决办法 |
|------|------|---------|
| `git merge` 报冲突很慌 | 不知道冲突标记的含义 | 看清 `<<<<<<<` `=======` `>>>>>>>` 三段分别代表谁 |
| 分支名写错 | 手误 | `git branch -m 旧名 新名` 重命名 |

## 今日收获

- 分支不是"复制一份代码"，而是一个指向提交的指针，很轻量。
- 养成"改之前先开分支"的习惯，主线永远是干净的。
